## V22（同日续）用户追问：失败相册定位 + 自动探索 + 剩余建议

用户给的真实案例：`https://xchina.co/photo/id-69ad45698f836.html`，其中一张图在
`https://img.xchina.io/photos2/69ad45698f836/0001.jpg`（注意 **photos2** 与 **4 位序号**）。

### 根因（两个叠加）
1. **CDN 子路径变了**：站点配置写死 base = `img.xchina.io/photos`，该相册实际在 `photos2`。
   枚举 `photos/...` 全部返回 `200 text/html`（越界页）→ probe 判 MISSING → 连错 3 次停止
   → 0 资源 → failed。**用户只看到失败，看不出是路径不对。**
2. **看门狗误杀（真正的致命伤）**：修好 1 之后任务跑到 extracting 又被标 failed，
   报 `invalid transition extracting -> downloading`。查日志发现
   `watchdog: stale task marked failed` —— **8060 与 8080 两个后端实例共用同一个
   `data/smoke.db`**，8060 的看门狗在进程内 `_active` 里找不到 8080 正在跑的任务
   （`_LIVE_MANAGERS` 是进程内列表），就把一个正在枚举 114 张图的任务判死了。

### 落地
- **CDN 基址 + 序号宽度自动探测**（`gallery_base._resolve_base`）：
  默认基址先用，**不中才试探候选**（正常相册零额外请求 —— 这是被测试逼出来的：
  第一版无条件预探测，让 happy path 平白多一次请求，计数型假 session 立刻逮住）。
  输入是资源直链时，`parse_resource_hint()` 直接从 URL 读出基址与宽度（`photos2` + `{seq:04d}`）。
  候选探测时**同时试 4/5 位序号宽度**（相册 69ad45698f836 就是 4 位）。
  ⚠️ `hint` 必须传**用户原始输入**，传 gid 的话直链里的信息早丢了。
  ⚠️ `_match_score` 也要把 `base_candidates` 纳入前缀比对，否则 `photos2` 直链不认领 → 落 generic。
- **看门狗改判 DB 心跳**：`tasks` 加 `hb REAL`；`_heartbeat()` 同时写库。
  「本进程没在跑」≠「任务死了」—— 只有 `now - hb > stale_task_timeout` 才判死。
  顺带修了长耗时枚举期间心跳不刷新（采集日志回调节流 5s 刷新一次）。
- **429 退避**（`downloaders/base.py`）：429 走 `RateLimited`，按 `Retry-After`
  （秒/HTTP 日期）等待，而不是套 8 秒封顶的普通退避。
- **任务级代理**：`options.proxy` 透传到 `discover(proxy=)` / `_video_at_first_seq(proxy=)`；
  全局 `settings.proxy` 仍在。
- **广告位识别**（`filters.exclude_ad`）：按**路径分段精确匹配**（`/ad/`、`banner_*.jpg`），
  绝不做子串包含 —— 子串会误杀 `downloads/badges/1.jpg`。

### 验证（决定性）
- 单实例重跑该相册：**114 张真图 / 56.1MB / 全部 JPEG 魔术字节 `ffd8ff` / status=success**，
  落 `downloads/1/69ad45698f836/0001.jpg`（4 位序号，正是 photos2）。
- pytest **296**（+ test_http_guard 4）；verify_output 33 / verify_hls 18。
- resolve 无歧义：裸 ID→gallery(10)、相册页→gallery(100)、视频页→video(100)、
  photos2 直链→gallery(50)、m3u8 直链→video(50)。

# V23（同日续）— HLS 加固 / 429 冷却 / 像素过滤 / sidecar / 页面线索

**沙箱网络本回合恢复可用**（此前 `requests` 直连被 SSL 拦），因此顺带把几个
"必须真站验证"的判断做掉了。

### 落地
- **HLS 加固**（`hls.py`）：`#EXT-X-KEY` **多密钥轮换**（逐把去重验可达）+ **相对密钥 URI**
  按 playlist 路径拼绝对；`video.py` 的 ffmpeg 加 `-reconnect*` 与 `-allowed_extensions ALL`。
- **429 域级冷却**（`ratelimit.py`）：按 `site_key` 共享冷却，`clear_cooldown`/`Retry-After`
  统一入口；`base.py` 收到 429 时先看冷却再决定等多久。
- **像素层过滤**（新 `core/imageinfo.py` + `filters.min/max_width/height`）：纯 Python 读文件头
  （JPEG/PNG/GIF/BMP/WEBP 含 VP8/VP8L/VP8X），**下载后**判定，只作用于 image。
  ⚠️ 复用文件命中去重时**绝不删别人的文件**。
- **元数据 sidecar**（`manifest.write_album_meta` → `<task_id>/album.json`）：
  **下载前**写出，任务全失败时它就是唯一的排查线索。
  内容 = 相册名/标签/厂牌 + **`resource_roots`**（实际生效的 CDN 基址、序号格式、
  `source`=页面线索/直链/探测、`site_default`）。
  ⚠️ 踩到并修掉：`log` 回调可能只接受一个参数（`list.append`），附属产物的日志
  **不该能把任务搞挂** → 统一 `_safe_log(fn, msg)`。
- **相册页 HTML 自带真实 CDN 前缀**（最重要的一项）：`album_meta` 新增
  `_resource_urls()` 从页面里抽出媒体直链，`discover(page_hints=...)` 把它当**第一手线索**
  （零探测）。`_resolve_base` 现在按可信度收多条线索：页面引用 → 用户直链 → 候选×宽度。
- **预览补 `resource_roots` / `warning`**：零枚举时用线索推断的序号位数渲染示例文件名
  （此前无论 4 位还是 5 位都写死 `00001`，用户照预告核对会以为命名错了）；
  采到 0 个时预告带可行动提示，前端新增 `res-root` / `pre-warn` 样式。
- **正则加固**：`parse_resource_hint` 遍历**全部候选根**、支持变体后缀
  （`00046_600x0.webp`）、用 `(?P<gid>)` 与 gid 交叉校验（页面里混着推荐位别的相册）。

### 真站探测结论（聚合页 URL 结构 —— 这次拿到了）

**规律：落地/索引页开放，全量列表页 CF 保护。**

`series-6443d480eb757` —— 但形状门 `[0-9a-f]{8,}` 一看就否掉。**这条门不能拆。**
