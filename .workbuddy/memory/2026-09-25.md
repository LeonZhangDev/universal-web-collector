## 三条设计纪律（各有一条用例钉住）

1. **评分上限由后端硬拦**（越界 400）。评分会被 `min_rating` 消费，一个 7 星会让"≥5 星"说不清。
   `0` = 未评分，**不是 0 分** —— "未评分"筛选必须读列，不能靠"看起来没星星"去猜。
2. **体检视图的 0 就是 0**。空库上九维都要有条目且 `n=0`，不是空列表（第 26 条）。
   未知维度键 **400**，不静默忽略（否则表现为"点了没反应"）。
3. **重复分组的 `keep_reason` 是代号**，中文由 `reasons` 下发；三条理由（像素最高/体积最大/最早）
   各有一条用例走它自己的那条路 —— 混在一个断言里等于没人验"理由对不对"。

1. **资源库排序** `GET /library?sort=&order=`。档位表 `LIBRARY_SORTS` 是**唯一翻译点**

### ⚠️ 顺手记一个本机 Bash 的坑

## V44 收尾：推送后 CI 红 —— 门禁**第四次**救场，但这次是个新机制

推上去之后 backend job 红 1 条（frontend 绿、docker skipped）：

```
AssertionError: 结构门禁红了: {'unused-imports': ['unused-import', 'unused-import']}
```

而本机六闸是全绿的。**两处判据都是纯文本正则、与平台无关**，所以差异只可能来自
**扫到的文件集合** —— 根因：`gateguard.tracked_files()` 按 `git ls-files` 扫，
而**我跑门禁时新文件还没 `git add`** ⇒ 本机那句"全绿"其实是**没验到那个新文件**
（红的是 `tests/test_features_v44.py` 里 2 个残留 import：`os` / `subprocess`，
是我删掉一条"逻辑本来就该报错"的用例后剩下的）。

⇒ **第 29 条：门禁只扫 git 跟踪的文件，新文件入库前就是"没验到"。纪律：跑门禁前先 `git add`。**

顺带修的三处（都有用例钉住）：

| 补了什么 | 为什么 |
| --- | --- |
| 删掉那 2 个残留 import | 真正的缺陷 |
| `test_the_real_repo_has_no_structural_problems` 报错带 `p.message` | 只给 `kind` 时，CI 上红成 `['unused-import','unused-import']`，哪两个文件得另写脚本复现 ⇒ **代号管"红不红"，文案管"哪里红"**（同族 K） |
| `gateguard.untracked_sources()` + CLI 提示（有条数、点名到文件、**不计入红绿**） | "没验到"必须看得见；算红就会因为临时脚本假红，而假红的下场是被加进豁免清单 |
| `SKIP_DIRS` 加 `.worktrees` | git worktree 有自己的 index，不该由本仓库门禁判；本机刷出 102 条噪音（CI 上没有这个目录） |

还栽了一个小的：**往"文件末尾"追加前没读到真正的末尾**，插入点把原函数的最后一行
切给了新函数 ⇒ 新用例 `NameError: name 'files' is not defined`。
判据：追加后 `git diff HEAD -- <file>` 目视，**必须只有 `+` 没有 `-`**（同族 L）。

**最终验证**：收集 **1400** → **1394 passed + 6 skipped**（独立 `--basetemp` 拿到汇总行；
不带 `--basetemp` 时 pytest 收尾清 135 个垃圾目录被 safe-delete 守卫拦下，没有汇总行 ——
判据是进度行有没有 `F`）；六闸全绿（16/3/**137**/6/**142**/**190**）。

**取 CI 日志的两个坑**：① GitHub 日志端点 302 到 blob storage，重定向时**必须摘掉
`Authorization`**（不然 401）；② 本机代理偶发 `Tunnel connection failed: 502`，请求要重试。
